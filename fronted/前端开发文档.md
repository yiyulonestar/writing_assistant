# 前端开发文档 —— 长篇小说 / 网文创作辅助 Agent

> 本文档基于**后端已完成的接口**（`backend/` 现有代码 + `使用说明.md`）编写，目标是给出一套**开发最快、技术栈最少**的前端落地方案与阶段性任务拆解。
>
> 后端技术栈：FastAPI + Tortoise ORM + PostgreSQL(pgvector)，接口基路径 `/api/v1`，Swagger 文档在 `http://localhost:8000/docs`。
> 前端目录为 `fronted/`（当前为空，从零开始）。

---

## 一、概述与目标

做一版**单用户本地工具**形态的 Web 前端，覆盖后端全部能力，形成「设定 → 生成 → 审稿 → 重写」的完整闭环：

| 能力 | 前端呈现 |
|------|----------|
| 小说管理 | 小说列表 + 新建 / 编辑 / 删除 |
| 结构化设定管理 | 角色 / 世界观 / 时间线 三个 Tab 的 CRUD 表单 |
| 章节写作 | 章节列表 + 正文编辑 + 大纲 / 摘要 / 状态 |
| 多步生成 | 单章 / 批量生成，WebSocket 进度条 + 审稿报告展示 |
| 一致性审稿 | 生成结果里的冲突 / 问题 / 修复状态可视化 |
| 交互式重写 | 按段落局部重写（下拉弹窗） |
| 草稿版本 | 版本历史列表 + 两版 diff 对比视图 |

**核心诉求**：开发快、依赖少、可维护。为此刻意不引入路由、状态库、UI 框架、HTTP 库，只保留「框架 + 构建」两个依赖（见下）。

## 二、技术栈选型（最小化）

### 2.1 推荐方案（主选）

| 层 | 选型 | 说明 | 为什么不用更重的 |
|----|------|------|------------------|
| 构建 / 开发服务器 | **Vite** | dev server + 代理（顺带解决 CORS）+ 打包 | —— |
| 框架 | **Vue 3**（Composition API + `<script setup>`） | 响应式 + 单文件组件 | 相比 React 上手更快、模板直观 |
| HTTP | 原生 **`fetch`** | 封装成 `api.ts` | 不引 axios，够用 |
| 实时进度 | 原生 **`WebSocket`** | 封装成 `ws.ts` | —— |
| 状态 | Vue **`reactive()`**（单个 `store.ts`） | 全局选中小说 / 列表缓存 | 不引 pinia |
| 路由 | **不引 vue-router**，视图切换用响应式标志 | 单页应用 | 5~6 个视图，不值当 |
| 样式 | 纯 CSS（可选 `Pico.css` 快速美化） | 手写为主 | 不引 UI 框架 |

**最终依赖只有 `vue`（运行时）+ `vite`（开发期）**，其余全部原生。这已经是能支撑「8 类资源 + 生成流水线」的最简组合。

### 2.2 更极简备选（无构建）

Vue 3 global 构建走 CDN + 纯 HTML/CSS/JS 单文件，**零依赖、零构建**。

- 优点：无需 Node / 安装依赖，双击 `index.html` 即可跑。
- 代价：失去 SFC / 模块化 / 热更新 / 构建；代码量一大就难维护。（跨域后端现已放行，不再是障碍）

> 结论：**主选方案**。备选仅用于「先跑个 demo 验证接口」时临时起一个 `index.html` 联调。

## 三、环境与联调

### 3.1 CORS（后端已处理）

后端已在 `app/main.py` 配置 `CORSMiddleware`，允许来源由 `.env` 的 `CORS_ORIGINS` 控制（默认 `http://localhost:5173,http://127.0.0.1:5173`，即 Vite 默认端口）。前端**可直接跨域访问** `http://localhost:8000`，无需代理。

| 方案 | 做法 | 适用 |
|------|------|------|
| **A. 直连后端（默认）** | 后端已放行 5173，前端直接请求 `http://localhost:8000/api/v1` | 开发期最省事，零配置 |
| B. Vite 代理 | `vite.config.ts` 把 `/api`、`/generate/ws` 代理到 8000，前端用相对路径 | 想用相对路径 / 后端换了端口 |
| C. 同源部署 | `vite build` 后由 FastAPI `StaticFiles` 挂载静态产物 | 生产期，单进程单端口 |

- **开发期默认走 A**（后端 CORS 已放行）；若希望前端代码不写死主机名，可改走 B。
- **生产期走 C**（同源，无跨域）。
- 前端若不在 5173 端口（换端口 / 局域网访问），在 `.env` 的 `CORS_ORIGINS` 追加来源即可（逗号分隔），改后重启后端。

### 3.2 代理配置参考（方案 B，可选）

> 仅当选择 Vite 代理（方案 B）时需要；默认方案 A 可跳过本节。

```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:8000', changeOrigin: true },
      '/generate/ws': { target: 'ws://localhost:8000', ws: true },
    },
  },
})
```

### 3.3 鉴权

后端若在 `.env` 配置了 `API_KEY`，则 **生成类接口**（`/generate/chapter`、`/generate/agent`、`/generate/batch`）需要请求头：

```
X-API-Key: <你的 Key>
```

> 前端做法：`api.ts` 统一读一个全局常量 / 设置项，**所有请求都带上** `X-API-Key`（带在 CRUD 上无害），避免遗漏。

### 3.4 基地址约定

把 base URL 收敛到 `api/client.ts` 的**一个常量**，不要散落在各请求里：

- 方案 A（直连）：`const BASE = 'http://localhost:8000/api/v1'`
- 方案 B / C（代理 / 同源）：`const BASE = '/api/v1'`

切换部署形态只改这一处即可。

## 四、后端接口速查（前端视角）

> 全部以 `/api/v1` 为前缀；所有响应字段为 **snake_case**；主键 `id` 均为 UUID **字符串**。
> 通用约定：`PATCH` 部分更新（**只发改动的字段**）；`DELETE` 成功返回 `204 No Content`；错误统一返回 `{"detail": "..."}`（400/401/404/500）。

**草稿版本历史**

|------|------|------|

| GET | `/chapters/{id}/drafts/{version}` | 指定版本 |
| GET | `/chapters/{id}/drafts/{version}/diff?base=1` | 两版 unified diff，返回 `{from_version, to_version, diff: string[]}` |

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/chapters/{id}/rewrite` | body：`{start, end, instruction?}`，段落按**空行**分隔、下标从 0 起 |

### 4.7 生成 Generate

> ⚠️ 慢（分钟级），必须异步 + 进度 + 防重复提交。需 `X-API-Key`（若后端启用鉴权）。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/generate/chapter` | 单章生成（确定性流水线） |
| POST | `/generate/agent` | 多 Agent 生成（等价结果，可断点续跑，query 可带 `thread_id`） |
| POST | `/generate/batch` | 批量生成（串行），返回 `GenerateChapterResponse[]` |
| WS | `/generate/ws` | 进度推送（见 4.8） |

**请求体 `GenerateChapterRequest`**

```json
{ "novel_id": "uuid", "chapter_number": 1, "outline": "可选", "target_word_count": 3000 }
```

**批量请求体 `GenerateChaptersRequest`**

```json
{ "novel_id": "uuid", "start_chapter": 1, "count": 3, "target_word_count": 3000, "outlines": ["大纲1", "大纲2", null] }
```

**响应体 `GenerateChapterResponse`**

```json
{
  "chapter_id": "uuid",
  "content": "正文……",
  "word_count": 2890,
  "review": {
    "issues": ["……"],
    "conflicts": ["……"],
    "fixed": true,
    "summary": "……"
  }
}
```

- `review.conflicts` 为空 → 审稿通过；非空且 `fixed=false` → 已达回退上限仍有冲突。

### 4.8 WebSocket 进度推送（`/generate/ws`）

连上后**先发送** `GenerateChapterRequest` JSON，服务端边生成边推事件：

```json
{"stage":"planning","chapter":1}
{"stage":"retrieving","chapter":1}
{"stage":"generating","chapter":1}
{"stage":"reviewing","chapter":1,"round":1}
{"stage":"revising","chapter":1,"round":1}
{"stage":"persisting","chapter":1}
{"stage":"summarizing","chapter":1}
{"stage":"done","chapter":1,"chapter_id":"uuid"}
{"stage":"complete","chapter_id":"uuid","word_count":2890}
{"stage":"error","message":"..."}
```

前端把 `stage` 映射成进度步骤文案即可。

### 6.2 API 客户端（`api/client.ts`）

```ts
const BASE = '/api/v1' // 直连后端时改为 'http://localhost:8000/api/v1'（见 3.4）
const API_KEY = '' // 从设置项 / 环境变量注入；后端启用鉴权时填写

async function request<T>(method: string, path: string, body?: unknown): Promise<T> {
  const res = await fetch(BASE + path, {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(API_KEY ? { 'X-API-Key': API_KEY } : {}),
    },
    body: body === undefined ? undefined : JSON.stringify(body),
  })
  if (res.status === 204) return undefined as T            // DELETE 成功无 body
  const data = await res.json().catch(() => ({}))
  if (!res.ok) throw new Error((data as any).detail || `HTTP ${res.status}`)
  return data as T
}

export const api = {
  get:    <T>(p: string)            => request<T>('GET', p),
  post:   <T>(p: string, b: unknown) => request<T>('POST', p, b),
  patch:  <T>(p: string, b: unknown) => request<T>('PATCH', p, b),
  del:    <T>(p: string)            => request<T>('DELETE', p),
}
```

> PATCH 时在业务层用 `Object.fromEntries(Object.entries(payload).filter(([,v]) => v !== undefined))` 剔除未改字段，符合后端 `exclude_unset` 语义。

### 6.3 WebSocket 进度（`api/ws.ts`）

```ts
export function generateWithProgress(payload: GenerateChapterRequest, onProgress: (e: ProgressEvent) => void): Promise<GenerateResponse> {
  return new Promise((resolve, reject) => {
    const ws = new WebSocket(`ws://${location.host}/generate/ws`)
    ws.onopen = () => ws.send(JSON.stringify(payload))
    ws.onmessage = (msg) => {
      const e = JSON.parse(msg.data)
      if (e.stage === 'complete') { resolve({ chapter_id: e.chapter_id, content: '', word_count: e.word_count } as any) }
      else if (e.stage === 'error') { reject(new Error(e.message)) }
      else onProgress(e)
    }
    ws.onerror = () => reject(new Error('WebSocket 连接失败'))
  })
}
```

> 注意：`/generate/ws` 只回传进度与 `chapter_id`/`word_count`，**不回传正文**。若要在生成完成后展示正文，拿到 `chapter_id` 后再 `GET /chapters/{chapter_id}` 拉正文。单章生成若直接要正文，用 `POST /generate/chapter`（HTTP）即可，此时正文随响应返回。

## 七、页面与交互规划

单页应用，左侧固定侧边栏，顶部展示当前小说名。选中小说后四个主视图：

1. **小说列表**（`NovelList.vue`）：卡片 / 表格 + 「新建」按钮 → 弹窗表单。选中即进入工作台。
2. **设定工作台**（`SettingsView.vue`）：三个 Tab（角色 / 世界观 / 时间线），各自列表 + 新建 / 编辑（弹窗表单）/ 删除（二次确认）。
3. **章节列表 + 编辑**（`ChapterList.vue` + `ChapterEditor.vue`）：左列表、右正文编辑器（`textarea`，字数实时统计），顶部可编辑大纲 / 摘要 / 状态；「版本历史」抽屉 + 两版 diff；「局部重写」弹窗。
4. **生成面板**（`GenerateView.vue`）：单章 / 批量切换，填写大纲与目标字数 → 提交后展示进度步骤条 → 完成后展示审稿报告（issues / conflicts / summary / 是否已修复）。

通用交互约定：
- 所有增删改后**就地刷新当前列表**，不做乐观更新（数据一致性优先）。
- 生成中禁用「生成」按钮、展示进度，**防止重复提交**。
- 错误统一用顶部 `toast` 展示 `detail` 文案。

## 十、风险与注意事项

1. **CORS**：后端已配置 `CORSMiddleware`（`CORS_ORIGINS` 控制，默认放行 5173）。若前端端口 / 来源变化，需同步更新 `.env` 的 `CORS_ORIGINS` 并重启后端（见 3.1）。
2. **字段名 snake_case**：前端 JSON 必须用 `novel_id` / `word_count` / `involved_character_ids` 等，**勿转 camelCase**，否则后端校验丢字段。
3. **`PATCH` 部分更新**：只发改动的字段，发 `null` 会把字段置空（符合预期），发 `undefined` 会因 JSON 序列化被丢弃——注意用 6.2 的过滤写法。
4. **生成接口慢**：单章可达分钟级，审稿模型较大。前端必须异步 + 进度 + 防重复提交；建议先小 `target_word_count` 试跑。
5. **`/generate/ws` 不回传正文**：需要正文时按 `chapter_id` 再 `GET /chapters/{id}`。
6. **删除是级联**：删小说会连带删角色/章节/时间线/世界观，前端删除小说需更醒目的二次确认。
7. **embedding 冷启动**：首次保存角色/世界观/时间线可能慢（本地模型加载），表单要有 loading，勿误判超时。
8. **`DELETE` 返回 204**：`fetch` 解析前先判断 `204`，否则 `res.json()` 会抛错。
9. **审稿 `fixed=false` 仍有冲突**：前端要在审稿报告里**高亮未解决冲突**，提示用户人工介入，而非静默通过。
10. **UUID 全为字符串**：不要当 number 处理；时间线 `involved_character_ids` 是多选角色，需先拉角色列表渲染选项。
